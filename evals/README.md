# 모델 행동 평가

`tests/`는 가짜 모델 응답으로 코드를 검사합니다. 이 디렉터리는 실제 모델을 호출하되
외부 가격·재무·뉴스·종목 목록·재사용 시계를 고정하여 행동 변화를 비교합니다.
샘플 숫자와 기사는 합성 자료이며 실제 기업 분석에 사용할 수 없습니다.

프로젝트 루트에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe evals/run.py
.\.venv\Scripts\python.exe evals/run.py --live --case clarify_then_reuse
.\.venv\Scripts\python.exe evals/run.py --live
.\.venv\Scripts\python.exe evals/run.py --report evals/results/결과파일명.json
```

기본 실행은 API를 호출하지 않습니다. `--live`는 `.env` 또는 환경변수의 키와 모델을
사용하며 비용이 발생합니다. 첫 실험은 시나리오 하나만 실행하는 것을 권장합니다.
한 턴은 최대 12회 모델 호출을 할 수 있습니다. 정확한 비용/토큰 수는 아직 집계하지 않습니다.

## 평가 항목

- 종목/관점 유지와 전환, 관점 미정에서 불필요한 조회 방지
- 재무 기간의 확대 조회와 축소 재사용, 공개 자료 개수
- partial/unavailable 전달 및 도구 오류 유무
- 고정된 도구 호출 순서나 정답 문장 대신 행동 조건 검사

`results/`에 질문·답변·체크별 성공 여부·실행 시간·도구 요청/결과·근거 연결을 저장합니다.
FAIL이면 터미널에도 실패한 검사 이름과 도구 순서·오류가 표시됩니다.
`--report`는 과거 결과를 읽어 설명만 출력하며 API를 호출하거나 점수를 바꾸지 않습니다.
`reuse_financials` 실패는 유효한 재무가 있는데 재조회했다는 효율 조건 실패입니다.
최종 재무 기간 오류(`finance_scope`, `finance_rows`)와는 별도로 해석해야 합니다.
같은 case ID와 turn끼리 비교하세요. 프롬프트 해시와 모델명도 기록합니다.
모델 출력은 비결정적이므로 한 번의 성공으로 안정성을 보장하지 않습니다.

자동 점수는 답변 품질 점수가 아닙니다. 숫자의 정확성, 자료 부족 설명, 결론의 근거
충실성은 결과 파일을 사람이 별도로 검토해야 합니다. 실시간 데이터 연결도 별도 검사입니다.
동일 질문으로 프롬프트 변경 전후를 반복 실행하되 동시에 데이터/코드/모델을 바꾸지 마세요.
API 오류로 한 턴이 실패하면 해당 시나리오의 후속 턴은 중단하고 skipped에 집계합니다.
